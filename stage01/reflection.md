# AI Reflection

Before using AI, I built a basic SmartCare appointment prototype using Python variables, lists, dictionaries and functions. The first version stored two appointments using separate variables. I then improved the program by using a list of dictionaries and functions to store and display appointments.

AI helped me understand how the appointment-booking function worked and helped me identify limitations in my program. It also suggested possible improvements and provided an alternative beginner-friendly implementation. One thing I noticed was that AI can make assumptions about how the program should work, so I could not simply assume that its code was correct.

I verified the AI-generated code by running it and testing different inputs. I tested a normal appointment, a blank patient name, duplicate appointments, and unusual values such as None. This helped me see how the program actually behaved rather than relying only on the AI's explanation.

The engineering work still remained with me. I had to understand the code, compare the human and AI versions, test the program and decide whether the AI suggestions were appropriate. This showed me that AI can be useful as a programming tutor, but I still need to understand, test and verify any code that it generates.
